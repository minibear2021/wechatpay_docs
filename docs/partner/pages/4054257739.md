## 一、验签模式与证书类型的区分

| 注意事项 | 说明、正确应该怎么做 | 不做会怎么样 |
| --- | --- | --- |
| 平台证书与微信支付公钥须择一使用 | 说明：同一商户号的平台证书与微信支付公钥作用相同，用于验证微信支付应答、验证回调签名和加密敏感字段，长期使用时应择一作为验签模式；切换期间允许并存，但必须按 `Wechatpay-Serial` 同时兼容两种模式。<br>正确应该怎么做：① 先梳理商户号关联的全部系统，选择平台证书或微信支付公钥作为目标模式；② 若从平台证书切为公钥，先完成全部项目的双模式验签兼容，再执行公钥灰度并确认两个比例均为 100%；③ 若从公钥切回平台证书，先确认系统已停止使用公钥，再按官方流程配置安全联系人并生成平台证书。<br>典型反例：只完成一个项目的模式改造就在商户平台启动切换，其他项目仍固定使用原证书或原公钥验签。<br>见 [4012068814-平台证书产品介绍](https://pay.weixin.qq.com/doc/v3/merchant/4012068814.md)、 [4012153196-微信支付公钥产品介绍](https://pay.weixin.qq.com/doc/v3/merchant/4012153196.md)、 [4012154180-如何从平台证书切换成微信支付公钥](https://pay.weixin.qq.com/doc/v3/merchant/4012154180.md)、 [4013038816-微信支付公钥常见问题](https://pay.weixin.qq.com/doc/v3/merchant/4013038816.md)、 [4015419357-如何从微信支付公钥切换成平台证书](https://pay.weixin.qq.com/doc/v3/merchant/4015419357.md)、 [4024350132-证书密钥概览](https://pay.weixin.qq.com/doc/v3/merchant/4024350132.md) | 多项目仍使用不同模式且未按序列号路由时，APIv3 应答或回调会因证书与公钥不匹配而验签失败，支付流程受阻。 |

## 四、APIv3密钥用途与重置

| 注意事项 | 说明、正确应该怎么做 | 不做会怎么样 |
| --- | --- | --- |
| APIv3密钥仅用于解密，不得替代验签 | 说明：平台证书公钥用于验证微信支付应答和回调签名，APIv3 密钥仅用于解密回调业务密文及下载平台证书时返回的证书密文，两者用途不同。<br>正确应该怎么做：① 使用应答或回调头中的时间戳、随机串、原始报文及签名构造验签串，使用 `Wechatpay-Serial` 对应的平台证书公钥验证签名；② 签名验证通过后，再使用 APIv3 密钥按 AEAD\_AES\_256\_GCM 解密回调通知的 `resource` 或平台证书下载结果；③ 不得以“已经能用 APIv3 密钥解开密文”代替消息真实性校验。<br>典型反例：回调代码只使用 APIv3 密钥解密通知资源，没有读取 `Wechatpay-Serial`、 `Wechatpay-Signature` 等请求头，也未执行签名验签。<br>见 [4012069411-平台证书常见问题](https://pay.weixin.qq.com/doc/v3/merchant/4012069411.md)、 [4012071382-如何解密回调报文和平台证书](https://pay.weixin.qq.com/doc/v3/merchant/4012071382.md)、 [4013053420-如何使用平台证书验签名](https://pay.weixin.qq.com/doc/v3/merchant/4013053420.md)、 [4024350132-证书密钥概览](https://pay.weixin.qq.com/doc/v3/merchant/4024350132.md) | 无法校验消息来源和报文完整性；若误将 APIv3 密钥作为验签密钥，签名验证会失败，回调通知无法正常处理。 |
| 重置APIv3密钥后须同步更新所有系统配置 | 说明：APIv3密钥用于解密平台证书下载结果和V3回调通知；修改后应联系技术人员在所有相关服务中替换，并测试服务可用性。<br>正确应该怎么做：① 重置前盘点使用同一商户号的全部应用、环境和历史服务，并确认APIv3密钥的保存位置；② 暂停相关服务或安排维护窗口；③ 在商户平台修改APIv3密钥；④ 同步更新全部系统中的新密钥并验证平台证书下载、回调解密和业务处理；⑤ 无法找回原密钥时，按此流程重置，不得只修改其中一个系统。<br>典型反例：只更新主支付服务，遗漏回调服务或其他调用方；重置后仍让部分服务保留旧密钥。<br>见 [4012071382-如何解密回调报文和平台证书](https://pay.weixin.qq.com/doc/v3/merchant/4012071382.md)、 [4012072195-配置APIv3密钥](https://pay.weixin.qq.com/doc/v3/merchant/4012072195.md) | 旧密钥立即失效后，平台证书下载结果的解密、V3回调报文解密会失败，支付结果和退款通知无法处理。 |

## 五、回调链路TLS根证书

| 注意事项 | 说明、正确应该怎么做 | 不做会怎么样 |

| 更换回调TLS根证书后须提前验证回调 | 说明：微信支付支持 `GlobalSign Root R46` 根证书；商户更换支付及退款回调服务所使用的TLS根证书前，应使用新的回调URL验证兼容性，测试由商户侧完成。<br>正确应该怎么做：准备承载新根证书链的回调URL，分别验证支付结果通知与退款结果通知能够完成HTTPS连接、签名验证及业务应答，再切换生产回调服务。 | 根证书兼容性不满足时，支付或退款回调无法正常到达商户，支付成功后的订单出票、发货或退款状态更新受阻。 |

## 七、商户API证书私钥保管

| 注意事项 | 说明、正确应该怎么做 | 不做会怎么样 |
| --- | --- | --- |
| 商户API证书私钥须妥善保管且丢失无法找回 | 说明：商户API证书私钥 `apiclient_key.pem` 只能通过证书工具导出，丢失后无法重新下载或找回，只能作废原证书并重新申请。<br>正确应该怎么做：① 申请新API证书后，将证书和私钥交由技术人员部署；② 私钥存入密钥管理或受限配置，禁止提交到Git、写入客户端代码或暴露在公共场合；③ 限制访问权限并保留交接记录；④ 怀疑泄露或丢失时，立即在商户平台作废原证书并申请新证书，完成部署后验证APIv3请求签名。<br>典型反例：将 `apiclient_key.pem` 提交到代码仓库或写入客户端代码；或只备份证书文件而未单独保管私钥。<br>见 [4011985891-安全规范](https://pay.weixin.qq.com/doc/v2/merchant/4011985891.md)、 [4012072428-申请商户API证书](https://pay.weixin.qq.com/doc/v3/merchant/4012072428.md)、 [4012365345-报错：商户证书序列号有误。请使用签名私钥匹配的证书序列号](https://pay.weixin.qq.com/doc/v3/merchant/4012365345.md)、 [4012365347-状态码401或签名验签失败](https://pay.weixin.qq.com/doc/v3/merchant/4012365347.md)、 [4012551764-下载平台证书](https://pay.weixin.qq.com/doc/v3/merchant/4012551764.md)、 [4013053057-如何更换商户API证书](https://pay.weixin.qq.com/doc/v3/merchant/4013053057.md)、 [4013058943-服务商如何更换商户API证书](https://pay.weixin.qq.com/doc/v3/partner/4013058943.md)、 [4013070756-开发必要参数说明](https://pay.weixin.qq.com/doc/v3/merchant/4013070756.md)、 [4024350132-证书密钥概览](https://pay.weixin.qq.com/doc/v3/merchant/4024350132.md) | 私钥丢失后无法生成APIv3请求签名，支付、退款等接口无法调用；必须作废原证书并重新申请、部署，期间业务可能中断。 |

## 八、商户API证书数量上限与作废恢复

| 注意事项 | 说明、正确应该怎么做 | 不做会怎么样 |
| --- | --- | --- |
| 同一商户号最多同时生效3份商户API证书 | 说明：一个商户号最多可同时生效 3 份商户API证书，机构号同样最多支持 3 张，旧证书在有效期内且未作废时可继续使用；新增证书会挤占有效名额，影响已有证书的有效性。<br>正确应该怎么做：新增或轮换商户API证书前先检查当前有效证书数量；需要新增时申请新证书并替换代码中的证书私钥和证书序列号，在确认旧证书调用量归零后再作废旧证书；④ 证书更换后在灰度或监控中确认全部调用方已切换到仍在有效期内的证书。<br>见 [4012072428-申请商户API证书](https://pay.weixin.qq.com/doc/v3/merchant/4012072428.md)、 [4013053057-如何更换商户API证书？](https://pay.weixin.qq.com/doc/v3/merchant/4013053057.md)、 [4024350132-证书密钥概览](https://pay.weixin.qq.com/doc/v3/merchant/4024350132.md) | 超过同时生效数量后无法继续新增商户API证书，证书轮换流程受阻；新增证书后原有证书被挤出有效名额，使用旧证书的下单、查单等接口调用失败，影响线上交易。 |
| 作废商户API证书后七日内可恢复 | 说明：商户 API 证书自作废之日起 7 日内仍可由商户号超级管理员取消作废并恢复使用，超过该期限后不能再恢复。<br>正确应该怎么做：① 作废前先申请并部署新证书，核对旧证书调用量是否归零；② 如需验证旧证书是否仍被业务使用，可作废后在 7 日内观察并随时恢复；③ 超级管理员登录商户平台【账户中心-账户设置-API安全-管理证书】，点击对应证书的“恢复”并完成安全验证。<br>典型反例：未先保留新证书和回退窗口便直接作废，随后发现仍有旧证书调用但已超过可恢复期限。<br>见 [4013053057-如何更换商户API证书？](https://pay.weixin.qq.com/doc/v3/merchant/4013053057.md) | 超过 7 日后旧商户 API 证书无法恢复，只能重新申请并部署证书；仍使用旧证书的服务会持续调用失败。 |

## 九、服务商证书按sp\_mchid维度维护

| --- | --- | --- |
| 服务商须按服务商号统一维护换证 | 说明：服务商代子商户发起 APIv3 请求时，使用服务商 API 证书私钥生成请求签名，并使用服务商对应的微信支付平台证书或微信支付公钥验证应答和回调；不同服务商的证书或公钥不同。<br>正确应该怎么做：① 以 `sp_mchid` 为维度维护服务商 API 证书、平台证书或微信支付公钥；② 请求签名使用当前服务商 API 证书私钥，请求头中的证书序列号与该私钥匹配；③ 应答和回调按 `Wechatpay-Serial` 从当前服务商证书集合中选择验签对象；④ 同时服务多个服务商或子商户时，分别建立证书映射，不跨服务商复用。<br>典型反例：多个服务商共用一套全局验签证书，或在服务商代调用场景改用子商户的其他平台证书。<br>见 [4012073044-产品介绍](https://pay.weixin.qq.com/doc/v3/partner/4012073044.md)、 [4012073146-服务商平台证书更换操作指引](https://pay.weixin.qq.com/doc/v3/partner/4012073146.md)、 [4012073263-常见问题](https://pay.weixin.qq.com/doc/v3/partner/4012073263.md)、 [4012925289-如何从平台证书切换成微信支付公钥](https://pay.weixin.qq.com/doc/v3/partner/4012925289.md)、 [4013038589-微信支付公钥常见问题](https://pay.weixin.qq.com/doc/v3/partner/4013038589.md)、 [4013080340-开发必要参数说明](https://pay.weixin.qq.com/doc/v3/partner/4013080340.md)、 [4025464285-服务商证书密钥概览](https://pay.weixin.qq.com/doc/v3/partner/4025464285.md) | 请求签名与证书序列号不匹配，或使用其他服务商的证书验签，将导致 APIv3 请求鉴权或应答、回调验签失败，相关子商户交易无法处理。 |
